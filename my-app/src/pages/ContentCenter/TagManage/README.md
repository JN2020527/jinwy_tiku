# 标签树维护原型说明

## 知识树维护 V0.2

### 运行与入口

- 运行：`npm run dev`
- 路由：`/preparation/knowledge-tree`
- 试题知识体系：`/tag-system/knowledge` 保持原页面、筛选语境、属性和导入导出能力，不与知识树共享对象语义。
- 数据：`src/services/tagSystem.ts` 与 `mock/tagSystem.ts` 成对维护，不依赖真实后端。

### 设计说明

- 知识树使用独立页面入口，并沿用 `TagSystemTreePanel` 的行内新增、重命名、删除确认和整理模式，不复制平行的树实现。
- `knowledgeTree` 是知识块知识树的独立 mock 数据域；`knowledge` 继续表示试题知识体系。两者复用树组件和 CRUD 代码，但不共享页面入口、树状态或节点 ID 命名空间。
- `structureOnly` 是共享组件的显式能力边界：知识树与资源树只维护当前学科树结构；试题知识体系、题型树、专题树等既有调用方继续保留自己的体系或属性能力。
- 知识树只展示系统学科目录、节点搜索和结构操作，不展示体系、同步语境、属性标签、导入导出或知识块关联入口。
- 新增和重命名在保存成功后重新读取当前树；失败时保留行内输入。拖拽不先修改本地树，保存成功后重新读取，失败自然保持原结构。
- mock 中知识块关联按稳定节点 ID 独立记录。数学节点“有理数”关联 3 个知识块，“三角形”关联 1 个知识块，用于验证新增子节点、接收拖入节点和删除守卫。
- mock 中学案三级考点项引用也按稳定节点 ID 独立记录（V0.5 / AC-20）。数学节点“有理数”另有 2 个学案引用（与知识块关联并存，验证两类数量同时提示），“无理数”有 2 个学案引用（无知识块关联，验证仅学案引用守卫）；移除全部引用后对应节点恢复可操作。
- 生物学科提供空树 fixture，用于验证空状态和新增根节点。

### 交互守卫

- 同一学科知识树内节点名称全局唯一，不同分支也不允许同名；不同学科可以同名。
- 节点不能跨学科移动，不能移动到自身或后代。
- 已关联知识块的末级节点可以重命名、排序或移动到其他父节点下并保持末级；不能新增或接收子节点。
- 存在学案三级考点项引用的末级节点同样可以重命名、排序或移动到其他父节点下并保持末级；不能新增或接收子节点（V0.5 / AC-20）。
- 节点仅在无子节点、无知识块关联且无学案三级考点项引用时可删除，删除前必须确认。
- 关联守卫显示相关知识块数量、学案引用数量（两类同时存在时都展示）和调整提示，但不在知识树页面提供关联或引用操作。

## 假设与待确认

- 已按冻结需求采用系统现有学科目录作为唯一学科来源，无产品待决策阻塞项。
- 将“失败后可重试”实现为保留行内输入后再次保存，或保持原树后重新拖拽、重新删除；未新增业务级失败任务或重试队列。
- 关联数量仅在操作受阻时展示，不常驻占用节点行空间；这属于不改变业务语义的视觉默认。
- 当前为纯前端原型，mock 关联 fixture 只用于验证结构守卫，不代表知识树页面能够创建知识块关联。
