- 页面：`/tag-system/attributes`

## 步骤记录

1. 默认工作台
   - 状态：健康。
   - 观察：年级/学科在顶部，分类在左，当前分类标签在右，主任务路径清楚。
   - 风险：左侧添加分类按钮只有图标，对新用户和触屏用户不够直观。

2. 搜索标签
   - 状态：基本健康。
   - 观察：搜索能立即过滤当前分类标签。
   - 风险：过滤后缺少“已筛选 N 项 / 清空筛选”的状态提示，用户可能不确定列表为何变少。

3. 快速添加标签
   - 状态：健康。
   - 观察：输入标签名后点击添加，标签进入当前分类，输入框清空，有成功反馈。
   - 风险：没有重复标签校验提示；同一分类下可能误加重复标签。

4. 编辑标签弹窗
   - 状态：可用但有上下文弱点。
   - 观察：弹窗轻量，只编辑标签名，路径短。
   - 风险：弹窗里没有显示“当前分类 / 年级 / 学科”，用户在跨分类维护时容易失去上下文。

5. 删除确认
   - 状态：可用。
   - 观察：确认文案包含标签名，能阻止误删。
   - 风险：删除确认的主按钮仍是蓝色“确定”，危险操作的视觉语义不够强；建议用 danger 样式。

6. 切换分类
   - 状态：健康。
   - 观察：切换到“考查能力”后右侧内容刷新，搜索状态被清空，符合用户预期。

7. 移动端重排
   - 状态：基本健康。
   - 观察：无横向溢出，分类区和工作区上下排列。
   - 风险：移动端分类列表高度较高，工作区会被推到较下方；如果分类很多，用户进入标签区前需要较多滚动。

## 强项

- 信息结构从“表格行操作”变成“分类导航 + 标签工作台”，维护任务更直接。
- 年级/学科上下文保留在页首，符合属性标签按上下文配置的业务需求。
- 快速新增标签入口显著，适合高频配置。
- 搜索、切换分类、新增标签的反馈链路清楚。
- 窄屏下没有横向溢出，布局能重排。

## 主要风险

1. 图标操作对新用户不够自解释
   - 添加分类、编辑分类、删除分类、编辑标签、删除标签主要依赖图标和 Tooltip。
   - 对鼠标用户尚可，对触屏用户和键盘/读屏用户不够友好。

2. 编辑/删除操作缺少足够上下文
   - 编辑标签弹窗只显示标签名，不显示当前分类和年级/学科。
   - 删除确认只显示标签名，不显示分类；如果不同分类有同名标签，确认成本会上升。

3. 可访问性语义不足
   - 分类按钮没有 `aria-selected` 或 `aria-pressed`。
   - 多个图标按钮没有 `aria-label`，读屏器难以区分“编辑哪个标签”“删除哪个标签”。

4. 批量维护能力不足
   - 当前适合少量标签维护。
   - 如果一个分类下几十个标签，缺少批量添加、批量删除、导入、排序等效率工具。

## 建议

1. 把左侧“添加分类”从纯圆形图标改成“+ 添加分类”文本按钮，至少在桌面端显示文字。
2. 给所有图标按钮补 `aria-label`，例如“编辑标签：容易”“删除分类：难度”。
3. 编辑标签弹窗增加只读上下文行：`七年级 / 数学 / 难度`。
4. 删除确认增加分类上下文，并把确认按钮改成危险样式。
5. 搜索后展示结果状态，例如“匹配 2 个标签”，并提供清空筛选。
6. 后续如果标签量增大，增加“批量添加标签”入口，支持一行一个标签快速录入。

## 证据限制

- 本次审查基于截图、DOM 状态和局部交互测试。
- 未完整测试键盘 Tab 顺序、读屏器朗读结果、真实后端错误态和大量数据性能。
