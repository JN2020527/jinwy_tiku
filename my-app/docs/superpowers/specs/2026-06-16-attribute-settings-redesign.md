# 属性设置重构设计规格

## 背景

当前属性设置页面把“属性创建”和“属性使用”放在同一套配置里，导致运营在创建属性时需要同时理解上传、打标、前台展示、筛选、必填、字段编码等规则。随着业务规则被澄清，这种自由组合已经超过了当前需要。

新的核心判断是：属性先被定义为一种业务信息，再被不同业务场景引用。创建属性时只回答“这个属性是什么”，使用设置时再回答“这个属性在哪里生效、是否必填、排序如何”。

## 业务规则

属性分为两类：

- 试卷属性：隶属于试卷整体，用于上传信息完善、前台展示、前台筛选和管理端查看。
- 试题属性：隶属于试题，用于下游试题打标和管理端查看。

场景约束固定为：

| 属性类型 | 上传信息完善 | 打标加工 | 前台展示 | 前台筛选 | 管理端查看 |
| --- | --- | --- | --- | --- | --- |
| 试卷属性 | 支持 | 不支持 | 支持 | 支持 | 默认支持 |
| 试题属性 | 不支持 | 支持 | 不支持 | 不支持 | 默认支持 |

试题和试卷存在隶属关系，上传按试卷整体进行，所以试题属性不进入上传环节。打标针对试题进行，所以试卷属性不进入打标环节。前台展示与前台筛选是两个不同用途，均只面向试卷属性。

## 设计目标

1. 将属性本体和业务使用配置拆开，降低运营理解成本。
2. 删除无效组合，避免试卷属性参与打标、试题属性参与上传等配置错误。
3. 保留运营真正需要的动作：创建属性、维护枚举值、启停、拖拽排序、配置场景使用。
4. 为后续上传页、打标页、前台列表消费属性配置提供清晰的数据结构。

## 非目标

- 不在主流程暴露属性编码、取值字段、字段类型、控件类型。
- 不支持试题属性前台展示或前台筛选。
- 不支持试卷属性打标。
- 不支持试题属性上传信息完善。
- 不拆分前台展示名称和属性名称。前台默认使用属性名称。
- 不为枚举值配置颜色、独立前台名称或独立前台可见性。

## 信息架构

属性设置页保留为一个菜单，但页面内拆成两个主区：

### 属性定义

用于维护属性本体。

字段：

- 属性类型：试卷属性 / 试题属性。
- 属性名称。
- 启用状态。
- 属性排序。
- 枚举值列表。
- 枚举值排序。
- 枚举值启用状态。

行为：

- 新增属性时必须选择属性类型。
- 属性名称是后台管理和前台默认展示共用名称。
- 枚举值以普通文本列表展示，不使用彩色标签。
- 枚举值支持拖拽排序，后台顺序即业务展示顺序。
- 停用属性后，该属性不再出现在使用设置和消费端。

### 使用设置

用于配置属性在哪些业务场景中生效。

按场景拆成四组：

1. 试卷上传
   - 可选择启用的试卷属性。
   - 支持设置是否必填。
   - 支持拖拽排序，决定上传表单字段顺序。

2. 前台展示
   - 可选择启用的试卷属性。
   - 支持拖拽排序，决定试卷卡片或详情页展示顺序。
   - 展示文案默认使用属性名称。

3. 前台筛选
   - 可选择启用的试卷属性。
   - 支持拖拽排序，决定前台筛选区顺序。
   - 筛选项文案默认使用属性名称。

4. 试题打标
   - 可选择启用的试题属性。
   - 支持设置是否必填。
   - 支持拖拽排序，决定打标表单字段顺序。

## 交互设计

页面建议使用 PC 端双层结构：

- 顶部：年级、学科筛选。
- 主体：左右布局。
  - 左侧为属性定义列表，可按“试卷属性 / 试题属性”分组或切换。
  - 右侧为当前属性的枚举值管理。
- 下方或独立页签为使用设置，按“试卷上传 / 前台展示 / 前台筛选 / 试题打标”展示。

属性定义区只出现定义相关内容。使用设置区只出现场景相关内容。用户选中某个使用场景时，只能看到该场景允许使用的属性类型。

## 数据模型建议

现有 `TagCategory` 可继续作为属性定义主体，但需要调整语义：

- `target` 收敛为 `paper` 或 `question`。
- `tags` 表示枚举值。
- `status` 表示属性启用状态。
- `sort` 可新增到属性层，用于属性定义排序。
- `code` 保留为内部字段，由系统生成，不在主界面展示。

新增或调整使用配置结构：

```ts
type AttributeUsageScene =
  | 'paperUpload'
  | 'paperFrontDisplay'
  | 'paperFrontFilter'
  | 'questionTagging';

interface AttributeUsageRule {
  id: string;
  attributeId: string;
  scene: AttributeUsageScene;
  enabled: boolean;
  required?: boolean;
  sort: number;
}
```

消费端按场景读取规则：

- 上传页读取 `paperUpload`。
- 前台展示读取 `paperFrontDisplay`。
- 前台筛选读取 `paperFrontFilter`。
- 打标页读取 `questionTagging`。

## 消费端规则

上传页：

- 只读取启用的试卷属性。
- 按 `paperUpload.sort` 展示。
- 对 `required` 为 true 的属性执行必填校验。

打标页：

- 只读取启用的试题属性。
- 按 `questionTagging.sort` 展示。
- 对 `required` 为 true 的属性执行必填校验。

前台展示：

- 只读取启用的试卷属性。
- 按 `paperFrontDisplay.sort` 展示。
- 属性名称作为默认展示文案。
- 枚举值按属性定义中的枚举值顺序展示。

前台筛选：

- 只读取启用的试卷属性。
- 按 `paperFrontFilter.sort` 展示。
- 属性名称作为默认筛选文案。
- 枚举值按属性定义中的枚举值顺序展示。

## 迁移策略

当前页面已有的 `contentCompletion`、`tagging`、`frontDisplay` 规则需要迁移为新的使用场景：

- `contentCompletion` 且属性为试卷属性，迁移为 `paperUpload`。
- `tagging` 且属性为试题属性，迁移为 `questionTagging`。
- `frontDisplay` 且属性为试卷属性，迁移为 `paperFrontDisplay`。
- 原 `displayRule.filterable` 为 true 时，额外迁移为 `paperFrontFilter`。
- 不符合新业务矩阵的旧配置在前端不再展示。

## 验收标准

1. 属性定义区不再出现上传、打标、前台展示、筛选、必填配置。
2. 使用设置区按四个业务场景展示，且每个场景只出现允许使用的属性类型。
3. 试卷属性无法配置打标，试题属性无法配置上传、前台展示、前台筛选。
4. 前台展示和前台筛选是两个独立用途。
5. 前台名称默认使用属性名称，主流程不要求重复填写。
6. 属性和枚举值均支持手动排序。
7. 枚举值列表使用克制的文本样式，不使用彩色标签。
8. 页面不再暴露属性编码、取值字段、字段类型、控件类型作为主流程字段。

## 实施顺序

1. 调整属性设置页的信息架构，拆分属性定义和使用设置。
2. 调整 mock 与服务类型，使属性定义和使用规则可以分开维护。
3. 保留现有属性和枚举值增删改能力。
4. 新增使用设置的四个场景配置。
5. 接入上传页读取试卷上传配置。
6. 接入打标页读取试题打标配置。
7. 为前台展示和筛选预留消费接口。
