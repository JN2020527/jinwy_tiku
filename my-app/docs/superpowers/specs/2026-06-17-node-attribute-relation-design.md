# 节点关联设计规格

## 背景

属性设置页当前已经分为 `属性定义` 和 `使用设置` 两个任务。

- `属性定义` 负责维护属性本体和枚举值，例如知识点属性“重难点”以及枚举值“重点 / 难点 / 易错点”。
- `使用设置` 负责配置属性在哪些业务场景中出现，例如“知识点树节点展示”或“专题树节点展示”。

但这两层还没有回答一个关键问题：某个具体知识点或专题节点到底对应哪个属性值。比如“有理数”是否是“重点”，“函数综合”是否是“高频”。因此属性设置页需要新增 `节点关联`，专门维护树节点和属性枚举值之间的关系。

本设计覆盖此前“节点属性值绑定在知识体系或专题体系模块完成”的旧判断。新的维护入口统一放在属性设置模块中，知识体系和专题体系页面只消费并展示关联结果。

## 设计目标

1. 在属性设置中完成知识点属性、专题属性和对应树节点的关联维护。
2. 保持属性定义、使用设置、节点关联三者职责清晰。
3. 支持同一个节点在同一个属性下只能选择一个枚举值。
4. 让知识体系和专题体系页面能展示已关联的属性值。
5. 第一阶段只服务树节点展示，不参与试题打标、试题筛选、组卷继承或统计分析。

## 非目标

- 不在知识体系或专题体系页面新增节点属性编辑入口。
- 不支持一个节点在同一个属性下选择多个枚举值。
- 不做矩阵式表格维护。
- 不做跨属性批量编辑。
- 不做试题对知识点属性的继承逻辑。
- 不做属性值统计分析。
- 不改变知识体系、专题体系现有树结构维护方式。

## 信息架构

属性设置页调整为三个一级 Tab：

1. `属性定义`
2. `使用设置`
3. `节点关联`

三者职责如下：

| Tab | 回答的问题 | 数据职责 |
| --- | --- | --- |
| 属性定义 | 有哪些属性和值 | 维护属性、枚举值、启停和排序 |
| 使用设置 | 属性在哪些场景出现 | 维护场景启用、展示顺序、筛选位置、必填规则 |
| 节点关联 | 哪些节点被赋了什么属性值 | 维护节点和属性枚举值的单选关系 |

`节点关联` 只支持知识点和专题两个对象类型。试卷属性、试题属性不进入该页面。

## 节点关联页面结构

页面采用三栏工作台。

### 左栏：属性选择

左栏顶部提供对象类型切换：

- 知识点
- 专题

切换对象类型后，下方展示对应对象类型下已启用的属性。

属性项展示：

- 属性名称。
- 枚举值数量。
- 已关联节点总数。

默认选中当前对象类型下第一个可用属性。如果没有可用属性，展示空状态并引导回到 `属性定义` 新增属性。

### 中栏：枚举值选择

中栏展示当前属性的枚举值列表。

每个枚举值展示：

- 枚举值名称。
- 当前已关联节点数量。
- 停用状态。

点击某个枚举值后，右栏节点树进入“给当前枚举值选择节点”的状态。

停用枚举值可以展示已有关系，但不可继续新增节点关联。已有关系可取消。

### 右栏：节点树勾选

右栏展示知识体系树或专题体系树。

右栏顶部提供：

- 学科筛选。
- 节点搜索。
- 当前编辑上下文提示，例如“正在为 重难点 / 重点 选择知识节点”。

节点树行为：

- 勾选节点：把该节点设置为当前枚举值。
- 取消勾选：删除该节点在当前属性下的关联。
- 如果节点已关联到同一属性下的其他枚举值，勾选当前枚举值时自动迁移到当前枚举值。
- 父节点和子节点默认不做级联勾选，第一阶段不提供“包含子节点”的批量赋值能力，避免误把整棵子树批量赋值。

## 用户路径

知识点示例：

```text
属性设置
-> 节点关联
-> 知识点
-> 重难点
-> 重点
-> 勾选“有理数”“整式”
```

专题示例：

```text
属性设置
-> 节点关联
-> 专题
-> 考频
-> 高频
-> 勾选“函数综合”“几何压轴”
```

## 数据模型

新增节点属性关系模型：

```ts
interface NodeAttributeRelation {
  id: string;
  targetType: 'knowledge' | 'topic';
  subject: string;
  nodeId: string;
  attributeId: string;
  optionId: string;
  updatedAt?: string;
}
```

唯一约束：

```text
targetType + subject + nodeId + attributeId
```

该约束保证同一学科下，一个节点在同一个属性中最多只有一个枚举值。

示例：

```text
targetType = knowledge
subject = math
nodeId = kp-1-1
attributeId = cat-knowledge-emphasis
optionId = knowledge-emphasis-1
```

语义：

```text
数学知识点“有理数”的“重难点”属性值是“重点”。
```

## 接口设计

### 查询节点关联

```text
GET /api/tags/node-attribute-relations
```

查询参数：

```ts
{
  targetType: 'knowledge' | 'topic';
  subject: string;
  attributeId?: string;
}
```

返回当前对象类型、学科、属性下的节点关联。`attributeId` 可选，用于消费端一次性查询多个展示属性。

### 设置节点关联

```text
PUT /api/tags/node-attribute-relation
```

请求体：

```ts
{
  targetType: 'knowledge' | 'topic';
  subject: string;
  nodeId: string;
  attributeId: string;
  optionId: string;
}
```

行为：

- 如果该 `targetType + subject + nodeId + attributeId` 不存在，新增关系。
- 如果已存在，覆盖原来的 `optionId`。
- 如果原来属于同属性下其他枚举值，自动迁移到新的枚举值。

### 删除节点关联

```text
DELETE /api/tags/node-attribute-relation
```

请求参数：

```ts
{
  targetType: 'knowledge' | 'topic';
  subject: string;
  nodeId: string;
  attributeId: string;
}
```

行为：

- 删除该节点在当前属性下的关系。
- 不删除属性定义。
- 不删除枚举值。
- 不影响树节点本身。

## 保存策略

第一阶段采用即时保存：

- 勾选节点时立即保存。
- 取消勾选时立即删除关系。
- 保存成功后更新枚举值关联数量和树节点勾选状态。
- 保存失败时还原本次交互并提示错误。

不设置全页保存按钮。原因是用户会频繁切换对象类型、属性、枚举值和学科，如果引入待保存状态，容易产生上下文混乱。

## 与使用设置的关系

节点关联只决定“节点有什么值”，不决定“页面是否展示”。

知识体系或专题体系页面是否显示该属性值，需要同时满足两个条件：

```text
节点存在属性关联
+ 该属性已在对应树节点展示场景中启用
= 展示属性值
```

知识体系展示规则：

```text
targetType = knowledge
+ 使用设置中启用 knowledgeTreeNodeDisplay
```

专题体系展示规则：

```text
targetType = topic
+ 使用设置中启用 topicTreeNodeDisplay
```

示例：

```text
有理数：
重难点 = 重点
目标分类 = 必会

使用设置中，知识点树节点展示只启用了“重难点”

知识体系页面显示：
有理数 [重点]

不显示：
[必会]
```

这样可以避免树节点被过多属性标签淹没，也保留 `使用设置` 的场景控制价值。

## 知识体系和专题体系展示

知识体系页面和专题体系页面不提供编辑入口，只展示已启用场景下的节点属性值。

展示逻辑：

1. 加载树数据。
2. 加载对应对象类型、学科下的节点属性关系。
3. 加载对应树节点展示场景下启用的属性规则。
4. 对每个节点匹配可展示的属性值。
5. 在节点标题后展示枚举值标签。

展示顺序：

- 按 `使用设置` 中树节点展示场景的属性排序展示。
- 同一个属性只有一个枚举值，因此无需处理同属性多值排序。

展示降级：

- 属性停用：不展示。
- 枚举值停用：知识体系和专题体系页面不展示该枚举值；节点关联页面仍可展示已有关系数量并允许取消关联。
- 属性未加入树节点展示场景：不展示。
- 关系指向不存在的节点、属性或枚举值：忽略并在 mock 或服务层清理。

## 删除和停用规则

删除属性：

- 删除属性定义时，应同步删除该属性下的节点关联。

删除枚举值：

- 删除枚举值时，应同步删除指向该枚举值的节点关联。

停用属性：

- 节点关联保留。
- 节点关联页面不再作为可选属性展示。
- 消费端不展示该属性值。

停用枚举值：

- 已有关联保留。
- 节点关联页面可展示已有数量。
- 不允许继续给新节点设置该枚举值。

删除节点：

- 删除知识点或专题节点时，应同步删除该节点的节点属性关联。

## 第一阶段范围

第一阶段实现以下能力：

1. 属性设置新增 `节点关联` Tab。
2. 支持知识点属性和专题属性的节点关联。
3. 支持按学科加载知识树或专题树。
4. 支持按属性和枚举值勾选节点。
5. 支持同属性单选迁移。
6. 支持即时保存。
7. 知识体系和专题体系页面展示已启用场景下的属性值。
8. mock 数据和 service 层补齐节点关联接口。

暂不实现：

- 批量导入。
- 继承到试题筛选或打标。
- 矩阵表维护。
- 多选属性。
- 跨学科复制。
- 包含子节点批量赋值。
- 节点属性统计分析。

## 验证点

1. 新增关系后，切换到同一枚举值能看到节点被勾选。
2. 同一节点从“重点”迁移到“难点”后，“重点”的关联数量减少，“难点”的关联数量增加。
3. 取消勾选后，该节点在当前属性下没有关联值。
4. 知识体系页面只展示 `knowledgeTreeNodeDisplay` 启用的知识点属性值。
5. 专题体系页面只展示 `topicTreeNodeDisplay` 启用的专题属性值。
6. 未加入树节点展示场景的关联值不在树节点上展示。
7. 删除属性或枚举值后，相关节点关联不会产生孤儿展示。
